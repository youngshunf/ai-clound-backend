# 生产可观测性部署说明

## 任务登记

- 任务：修复生产 OpenTelemetry 出口并完成安全加固
- 分支：`fix/prod-opentelemetry-security`
- worktree：`huanxing-cloud-backend/.worktrees/prod-opentelemetry-security`
- 目标仓库：`huanxing-cloud-backend`
- 目标主分支：`huanxing`

## 设计边界

- 生产应用继续由 Supervisor 在宿主机运行。
- OTLP/gRPC 仅发布到宿主机回环地址 `127.0.0.1:4317`。
- Grafana 仅发布到宿主机回环地址 `127.0.0.1:13000`，通过 SSH 隧道访问。
- Prometheus、Loki、Tempo 与 Alloy 管理界面不发布宿主机端口。
- 禁止使用仓库开发环境中的默认 Grafana 密码。
- 遥测数据持久化到 `/data2/huanxing-observability`，设置留存期限与资源上限。
- 公网 Nginx 必须拒绝访问 `/metrics` 与 `/metrics/`。
- 本变更不包含数据库迁移。

## 数据流

```text
Supervisor 应用
  -> 127.0.0.1:4317
  -> Alloy
     -> Prometheus（指标）
     -> Loki（日志）
     -> Tempo（链路）
  -> Grafana（仅容器内网络读取）
```

## 验收条件

- API、Celery worker 的 OTLP exporter 不再出现 `UNAVAILABLE`。
- Grafana 能查询 Prometheus、Loki、Tempo 三个数据源。
- 公网扫描无法连接 OTLP 与可观测性后端端口。
- `https://api.huanxing.dcfuture.cn/metrics` 和尾斜杠路径均不可读取指标。
- 生产业务 API 与六个目标 Supervisor 服务保持正常。

## 首次部署

生产目录：

```bash
OBS_ROOT=/data2/huanxing-observability
install -d -m 750 "$OBS_ROOT/config" "$OBS_ROOT/secrets"
install -d -m 750 \
  "$OBS_ROOT/data/alloy" \
  "$OBS_ROOT/data/grafana" \
  "$OBS_ROOT/data/loki" \
  "$OBS_ROOT/data/prometheus" \
  "$OBS_ROOT/data/tempo"
openssl rand -base64 36 > "$OBS_ROOT/secrets/grafana_admin_password"
chown root:root "$OBS_ROOT/secrets/grafana_admin_password"
chmod 440 "$OBS_ROOT/secrets/grafana_admin_password"
```

将 `production/` 与相邻的 `dashboards/` 同步到
`/data2/huanxing-observability/config/`。启动前按镜像默认 UID 设置数据目录属主；
实际 UID 必须通过 `docker image inspect` 核对，禁止给数据目录 `777` 权限。
Grafana 容器固定使用 `472:0`，因此密码文件需对 root 组只读；`0600` 会导致
容器内的 UID 472 无法读取密码。

```bash
cd /data2/huanxing-observability/config/production
OBS_DATA_DIR=/data2/huanxing-observability \
  docker compose config --quiet
OBS_DATA_DIR=/data2/huanxing-observability \
  docker compose pull
OBS_DATA_DIR=/data2/huanxing-observability \
  docker compose up -d
```

生产后端环境文件增加或更新：

```dotenv
GRAFANA_OTLP_GRPC_ENDPOINT=127.0.0.1:4317
```

`ENVIRONMENT=prod` 会启用 `GRAFANA_METRICS_ENABLE`，无需再开放任何 OTLP 公网端口。
更新环境后，只重启唤星目标服务，禁止 `supervisorctl restart all`。

## Nginx 指标收口

把 `observability-metrics-private.conf` 的两个 `location` 放入
`api.huanxing.dcfuture.cn` 的 HTTPS `server` 块，先执行 `nginx -t`，通过后再
reload。Prometheus 从容器内直接抓取宿主机 `8020`，不经过公网 Nginx。
观测网络固定为 `172.24.0.0/24`，Prometheus 固定使用 `172.24.0.250`；宿主机
防火墙只允许这个地址访问 `8020`：

```bash
ufw allow from 172.24.0.250 to any port 8020 proto tcp \
  comment 'huanxing prometheus scrape'
```

禁止给整个 Docker 网段或公网开放 `8020`。

公网预期：

```text
https://api.huanxing.dcfuture.cn/metrics   -> 404
https://api.huanxing.dcfuture.cn/metrics/  -> 404
```

## 访问 Grafana

Grafana 不提供公网 URL。先在本机建立 SSH 隧道：

```bash
env -u ALL_PROXY -u all_proxy -u HTTP_PROXY -u http_proxy \
  -u HTTPS_PROXY -u https_proxy \
  ssh -o ProxyCommand=none \
  -N -L 13000:127.0.0.1:13000 root@117.72.92.229
```

然后访问：

```text
http://127.0.0.1:13000
```

用户名为 `huanxing_admin`。管理员密码只保存在生产机
`/data2/huanxing-observability/secrets/grafana_admin_password`，属主为
`root:root`、权限为 `0440`；
禁止把密码写进仓库、部署记录或聊天消息。

## 安全控制

- OTLP 仅绑定宿主机回环地址；未启用公网、局域网或跨主机采集。
- Grafana 仅绑定宿主机回环地址；关闭匿名访问、注册、外部快照和插件管理。
- Prometheus、Loki、Tempo 与 Alloy UI 不发布宿主机端口。
- 容器使用只读根文件系统、丢弃全部 Linux capability、禁止提权、限制 PID
  、CPU 与内存。
- Alloy 删除常见凭据属性、URL 查询串、SQL 语句、用户标识和客户端地址。
- 日志、指标与链路默认只保留 7 天；生产数据目录位于 `/data2`。
- 可观测性网络关闭 Docker IP masquerade，不给容器提供公网 NAT；生产现场已验证
  宿主机回环端口转发可用、容器无法直接访问公网。
- 镜像固定到经过核对的官方稳定版本，升级前必须重新检查官方安全公告。

遥测日志正文仍可能包含业务代码主动写入的敏感内容。应用日志不得记录密码、
令牌、Cookie、完整请求体或用户私密内容；发现误写时必须先修日志源并删除对应
留存数据，不能依赖 Grafana 权限作为唯一防线。

- Grafana 三个数据源健康；
- Prometheus 能查询 `fba_requests_total` 等应用指标；
- Tempo 能查到新请求链路；
- Loki 能查到新日志；
- 最后一次服务重启后无新的 OTLP `UNAVAILABLE`；
- API captcha 为 200，六个目标 Supervisor 服务均为 `RUNNING`。

## 回滚

先在后端环境文件中显式关闭遥测并重启六个目标服务：

```dotenv
GRAFANA_METRICS_ENABLE=false
```

确认重启后没有新的 OTLP 导出请求，再停止可观测性栈：

```bash
cd /data2/huanxing-observability/config/production
OBS_DATA_DIR=/data2/huanxing-observability docker compose down
```

重新启用时应先启动并验证可观测性栈，再删除显式关闭项或改为 `true`，最后
重启六个目标服务。禁止用不存在的 `fba_alloy` 地址制造失败来“关闭”
OpenTelemetry。若永久移除 Prometheus，再删除精确的 `172.24.0.250 -> 8020`
UFW 规则；Nginx 的 `/metrics` 公网收口不随观测栈回滚。
