# hasn_task App — 工具说明（TOOLS.md）

> AI-Native App `hasn_task`（任务系统 + 多任务编排/工作流，模块 12）面向 Agent 的
> Tool API 规格说明。workflow 嵌于 task 模块（同 App、同目录、同 domain）。
> **运行时权威源是 DB JSONB manifest**（`hasn_ai_native_app_manifest.manifest_json`，
> builtin seed 见 `backend/app/hasn_task/service/ai_native_manifest.py` 的
> `HASN_TASK_AI_NATIVE_MANIFEST`）。本文件是人类可读规格，**必须与 manifest 一致**
> （由 `tests/mcp/test_app_tools_doc_consistency.py` 校验，零漂移）。

> 落地真相以 hasn-node `crates/hasn-mcp/src/task.rs` / `workflow.rs` 为准。

- scope 词表统一 `domain:action`（冒号）。task 三键：`task:read`/`task:manage`/`task:run`；
  workflow 三键：`workflow:read`/`workflow:manage`/`workflow:run`（六键均归 domain `task`，
  见 `backend/app/hasn_task/scopes.py`）。
- 维度① 能力授权（allow/ask/deny）统一适用本 App 工具；**默认出厂 `allow`**（16-doc D-v3-1），
  owner 可经 `capability_modes` 把各能力键设 ask/deny override。**例外**：`hasn.workflow.template.publish`
  出厂 **`ask`**（`human_confirmation.required=True`）——模板上架是外发+动钱语义，需主人确认。
- agent 建带定时（interval/cron）的任务/工作流落 `pending_approval` 业务态，由 owner 在
  任务列表行内确认——这是业务策略闸门，与维度①能力授权正交（不走 ask_gate）。
- `risk` 仅 UI 风险提示（D4），不强制确认；`delete`/`cancel` 标 high 仅作展示分级。
