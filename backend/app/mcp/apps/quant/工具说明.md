# quant App — 工具说明（TOOLS.md）

> AI-Native App `quant`（NautilusTrader 量化交易引擎接入，HExt-08，设计 doc23）面向 Agent 的 Tool API 规格说明。
> **运行时权威源是 DB JSONB manifest**（builtin seed 见 `backend/app/hasn_quant/manifest.py` 的 `build_quant_app()`
> + capabilities）。本文件是人类可读规格，**必须与 manifest 一致**（由 `tests/mcp/test_app_tools_doc_consistency.py`
> 校验，零漂移）。

> 形态：**cloud-brokered** 业务应用（对齐 creator/community/finance）。工具一律走云端 MCP
> （`transport=gateway_internal`，handler 落 `backend/app/mcp/apps/quant/quant_tool_handlers.py`）→
> `quant_service`（产品数据权威落 `hasn_quant` PG）→ `quant_engine_provider`（httpx）→ 独立部署的
> **quant-engine-service**（唯一接触 nautilus 的地方，跑真回测，重依赖隔离在独立服务）。
> 主云端进程**不引 nautilus**；Agent / WebUI **不直连**引擎服务，一律经主云端中转。
> 身份恒取自 Agent JWT（`owner_hasn_id`/`agent_hasn_id`，PLANFIX-6），owner 行级隔离。

⚠️ **本期（P0–P5 回测研究平台，零资金风险）只暴露回测/读/存（出厂 allow）**。实盘线
（`deploy_live`/`submit_order`/`resume`，出厂 **ask**，P6+）受 P0-闸1 产品/法务硬闸（做不做实盘资金托管），
本期不实现、不接真交易所。

| 工具 (mcp_name) | required_scopes | risk | 用途 |
|---|---|---|---|
| `hasn.quant.save_strategy` | `quant:write` | low | 保存/更新策略（源码或内置键 + 参数 + 标的）；不动钱，AI 生成策略走引擎沙箱执行 |
| `hasn.quant.list_strategies` | `quant:read` | low | 列出本主人的全部量化策略（行级隔离，最近优先） |
| `hasn.quant.get_strategy` | `quant:read` | low | 取单个策略详情（owner 隔离） |
| `hasn.quant.backtest` | `quant:backtest` | low | 提交回测（job 式，沙箱内跑历史/合成数据出绩效）：只花算力、不动钱，可随便迭代 |
| `hasn.quant.get_backtest` | `quant:read` | low | 读回测状态/绩效/净值曲线（非终态惰性轮询引擎落库；owner 隔离） |

- scope 词表统一 `domain:action`（冒号，见 13-doc §3.3 / P1）：回测/读/存三类全 `risk=low`、出厂 `allow`
  （`human_confirmation.required=False`，D-v3-1）——沙箱内、廉价、不动钱，分身可自由迭代。
- 维度① 能力授权（allow/ask/deny）统一适用；回测/读/存默认 `allow`，主人可设 ask/deny override。
- 维度②（企业角色裁剪）：个人模式（本期 `scope=('personal',)`），owner 行级隔离；企业双模归属为远期。
- **零 fake 与免责**：回测失败（引擎超时 / 不可达 / 策略代码报错）一律透传**真实**错误落 `error` 字段，
  绝不伪造绩效；回测结果**仅供研究参考，不构成投资建议**，历史绩效不代表未来收益。
- **安全**：AI 生成的 Strategy 源码在引擎服务进程沙箱（受限 import + 资源限额 + 一进程一节点）内执行，
  绝不在主云端进程跑用户代码。
