## 目标

1. 云端按稳定频道串行分配补丁版本并锁定唯一 release tag。
2. 第一台打包机器创建并推送 tag，后续机器自动加入同一发布批次并检出该 tag。
3. 任一平台上传完整的 installer/updater 后即可发布为最新版，其它平台继续加入同一版本与 tag 补齐资产。
4. 根据上一个 release tag 到当前 release tag 的 Git 提交历史，调用后端统一 LLM 服务生成不超过 200 个汉字的更新说明。
5. 重试必须复用批次、版本与 tag，不得重复加版本。
6. 数据库长期保留已发布版本，官网提供历史版本列表、版本说明和分平台下载入口。

## 落地契约

- `POST /api/v1/release/ci/prepare`：事务锁内创建或复用频道当前草稿批次，只增加一次 patch。
- release tag 使用 `v{version}`，指向第一台机器准备时的 `origin/main` commit；打包脚本幂等推送，云端通过 GitHub API 复核。
- `POST /api/v1/release/ci/batches/{id}/confirm-tag`：接收两个 tag 之间的 Git 提交；长历史分段调用统一 LLM，再汇总为 200 字以内说明。
- `POST /api/v1/release/ci/callback`：携 `release_id/release_tag` 后按平台和资产类型 upsert，不再整组删除。
- 任一受支持平台具有成对的 installer/updater，且 tag 与更新说明 ready 后，即可切换 `is_latest`；平台清单不充当发布门。
- `GET /api/v1/release/open/releases`：只返回 `published` 历史版本，官网据此展示旧版更新说明与下载入口。

## 构建隔离

tag 锁定源码 commit，版本号由云端分配。Windows/macOS 脚本在 tag 对应的专用 Git worktree
中同步修改 `apps/desktop/tauri.conf.json` 与 `apps/desktop/Cargo.toml` 后构建，确保安装包版本
与 Rust `CARGO_PKG_VERSION` 一致，同时不切换或污染开发主工作树。
